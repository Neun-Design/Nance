# Glossary

Domain and architecture terms for **nance.it**, as they are used in the current MVP. Especially useful for those arriving from UX/design or from outside the backend. The rendering concepts come from the *datamodel* — see [[Working with the Datamodel]] and, for the exact keys, `prototype/DATAMODEL_GUIDE.md`.

## Platform and domain

- **nance.it** — the platform (from *governance* — govern·nance.it). A **knowledge-driven governance** system where quality and governance obligations are *executed*, not just documented, generating audit evidence as a by-product of daily work.
- **EDQMS** (Event-Driven Quality Management System) — the **quality-management engine** of nance.it (modules Organization, Portfolio, Operation). The prototype and its code still carry the name (`EDQMS prototype`, `edqms-*` storage keys).
- **Knowledge management** — nance.it's other half: connecting **Workload** (task execution, the Workspace module) with **Talent** (user competencies), so obligations are matched to the people competent to execute them.
- **Vitalis** — *Vitalis Health Network*, the fictitious clinic chain of the demo dataset (`prototype/data/mockup_data_prototype.json`, generated by the seed from `tools/seed/domains/clinic.yaml`). Every name in it is invented.

## Screens

- **Module** — a sidebar entry. Today: **Organization**, **CRM**, **Operation**, **Portfolio**, **Workspace**, **Control**, **Talent** (in this order in the artifact), plus the **Overview**. Organization, Portfolio and Operation form the EDQMS core; Workspace and Talent add the knowledge dimension; CRM holds customers, SLAs and forecasts; Control holds capacity and performance.
- **Dashboard / Tab** — a screen inside a module. It renders, top to bottom: cards → data table → reports.
- **Overview** — a special dashboard assembled automatically from cards and reports marked `overview-display: true`.
- **Card** — a KPI above the table (main value, trend, detail), positioned by the grid coordinate `Card R-C`.
- **Report** — a chart below the table; its type and rule come from the datamodel.
- **Subitem table** — a per-row expandable child table (the chevron), filtered to that row's children.
- **Form / drawer** — the New Item / Edit panel of a table, driven by the `form` block (fields, widgets, checks, optional wizard `steps`).
- **Blank mode (MVP mode)** — the app with every table empty (`?data=empty` locally, `/app/mvp/` published), for modeling an operation from scratch. Records persist in the browser; the analytics-only surfaces are disabled.
- **Snapshot** — the JSON exported from blank mode (`_meta.kind: "blank-snapshot"`, stamped with `schemaVersion`), re-importable in any browser.

## Datamodel and engine

- **Datamodel** — the canonical specification of the system: authored in TypeScript in `packages/spec` (config-as-code, ADR-0002) and compiled to `prototype/data/datamodel.json`, the **artifact** the engine reads. Never hand-edited.
- **Model / View / Behavior** — the three layers of the spec: data shape (entities, attributes, relations) / layout (tables, forms, cards, reports) / behavior (checks, field rules).
- **Engine** — the code that interprets the artifact and resolves values at runtime. Today: the vanilla-JS modules in `prototype/js/` (`model.js` parses rules, `resolve.js` resolves relations, `queries.js` computes cards and reports, `forms.js` renders forms). In v1 it becomes a framework-agnostic TypeScript package.
- **Attribute** — a column/field of an entity, with `name`, `type`, `rule`, `constraints`, `notes`, and display flags.
- **Stored vs derived** — a *stored* attribute is persisted in the data; a *derived* one (`rollup`, `mirror`, `computed`) is recomputed by the engine on every render and must not appear in the data.
- **FK (foreign key)** — a reference to another entity; the UI displays the target's *display* field, never the raw id.
- **Rollup** — a derived value aggregating child records (`rollup → Entity (via: field)`).
- **Mirror** — a value copied at render time from a related record (`mirror → Entity (via: fk) (display: field)`).
- **Computed** — a value calculated by expression/path; `CONCAT` and `user input` are special cases.
- **Rule** — the one-line text on an attribute (`FK → Roles (display: roleName)`) that the engine parses into a relation. The spec emits it in the canonical spelling; the validator reads it with its own regexes.
- **schemaVersion** — the integer in `_meta` of the artifact and of every dataset/snapshot. +1 per PR that changes modules, tables, attributes or rules; migration scripts stamp it into the data; the app warns when a snapshot's version differs.
- **Build gate** — `npm run build` in `packages/spec` fails on Model errors (one PK per entity, targets that exist, …). A module may list a `suppress` entry only with the issue that will fix it; today the list is empty.
- **Derive, don't repeat** — principle: the View is derived from the Model (`formFor` derives a form's widgets from the attribute types); instances declare only exceptions.

## Data and tooling

- **Seed** — `prototype/tools/seed/build_seed.py`: the deterministic, catalogue-driven generator of the demo dataset. Same input → byte-identical output.
- **Migration script** — `prototype/tools/migrate_<slug>.py`: one deterministic, idempotent script per schema change that touches stored data.
- **Validator** — `prototype/tools/validate_mockup.py`: the parity contract between artifact and dataset.
- **Battery** — the 84 `prototype/tools/test_*.mjs` proofs (`test_engine_*`, `test_resolve`, `test_queries`, `test_jobs`), run with Node against the real artifact and dataset.
- **Anchored dates** — the dataset's dates shift forward from `_meta.anchorDate` on load, so the demo never ages.
- **ADR** — Architecture Decision Record; a decision recorded under `docs/adr/`.
- **Export contract / ETL** — the v1 plan (ADR-0003): a versioned snapshot format and an idempotent JSON → PostgreSQL loader. Decided, not built.
- **shadcn-vue** — the Vue implementation of the shadcn-style components chosen for the v1 frontend (ADR-0001).
